## 역할 제안
- 이민식: 팀장·기술 리드. 아키텍처, 공통 환경·배포, 에이전트 흐름·분류, 코드 검토. 김현나의 검색 구현과 김태연의 화면 구현 지원.
- 김현우: 서비스 기획·운영 정책·일정·결정 관리, 우선순위와 배정 정책, 인수 검증, 발표 스토리. 기술 구현 전체를 담당하지 않고 수용 기준과 사용자 관점 검증에 집중.
- 박민경: DB·API·티켓·Jira, 자동 배정, 상태 동기화, 중복 방지와 실패 복구.
- 김현나: 데이터 규격·검수, RAG 검색과 평가. 데이터분석 경력이 RAG 개발 경험을 보장하지 않으므로 구현 경험·선호를 확인하고 이민식이 지원.
- 고나영: UX/UI, PC·모바일 흐름, 예외 화면·문구, 디자인·사용성 검수. 프런트엔드 구현 경험을 전제하지 않음.
- 김태연: 챗봇·조회·대시보드 화면 구현과 API 연결. 작은 기능 단위로 이민식 검토, 고나영 디자인 협업. 첫 주 가능 범위를 확인해 난도 조정.

## 처리 정책 상세
문의 1건은 한 문제를 다루는 대화 1개입니다. 정보가 부족하면 영향 인원·업무 중단·오류 내용을 질문합니다. 명확한 긴급 상황은 추가 답변을 기다리지 않고 접수합니다. 직원의 직접 연결 요청도 허용합니다.

일반 문의는 매뉴얼과 검수된 해결 이력을 검색하고 근거가 있을 때 안내합니다. 근거가 없으면 담당자 연결을 제안하며, 사용자가 연결을 선택하면 티켓을 접수합니다. 사용자 확인으로만 AI 해결을 기록하고 무응답·이탈은 미확인으로 둡니다. 03.png의 A 표시는 미해결 경로가 오른쪽 티켓 접수로 이어진다는 뜻입니다. 미확인에서는 자동 접수하지 않습니다.

우선순위 초안: P1은 다수의 핵심 업무 중단 등 즉시 대응, P2는 주요 기능 중단·우회 어려움, P3는 일부 지연·우회 가능, P4는 일반 요청·업무 영향 낮음입니다. 인원 수 하나만으로 결정하지 않으며 김현우가 사례별 기준을 작성합니다.

## 상태와 저장 책임
문의 상태: 진행 중 / 해결 확인 / 담당자 이관 / 미확인.
티켓 상태: 접수 / 배정 / 처리 중 / 해결 / 종료.
연동 상태: 생성 대기 / 동기화 완료 / 생성 실패 / 배정 실패.

접수는 내부 기록 완료, 배정은 개인 담당자 지정 완료입니다. 팀 대기열만 지정된 건은 미배정입니다. Jira 생성 전에는 Jira 상태가 없으며, 생성 후 접수·배정은 To Do, 처리 중은 In Progress, 해결·종료는 Done에 대응하는 안입니다. 실제 Jira 워크플로에 맞춰 첫 주 검증합니다.

자체 DB는 문의·대화·접수 ID·집계 이벤트를 저장합니다. Jira 생성 후 담당자·처리 상태·조치의 기준은 Jira입니다. 해결 후 사용자 확인이 오면 내부 종료를 기록하고, 무응답이면 티켓은 해결 상태를 유지하며 사용자 확인 여부를 별도 저장합니다. 기존 건의 재발·미해결은 같은 티켓에 이어서 기록하며 필요시 처리 중으로 재개합니다.

30초 조회와 수동 새로고침은 동기화 제안입니다. 마지막 성공 시각을 표시합니다. 시간 초과 시 기존 티켓 존재 여부를 확인한 뒤 재시도하고, 생성 성공·배정 실패이면 배정만 재시도합니다. 모의 모드는 수동 선택, MOCK ID와 모드 배지를 표시합니다.

## 화면과 범위
직원은 자체 화면에서 본인 문의만 조회합니다. IT 담당자는 실제 Jira에서 상태 변경·조치 작성·재배정을 수행합니다. 관리자는 전체 대시보드와 배정 설정에 접근합니다. 실제 사내 로그인 연동은 제외하되 데모 계정의 접근 범위는 검증합니다.

필수 화면 상태는 첫 진입, 추가 질문, 답변 생성 중, 검색 근거 없음, 티켓 생성 중, 배정 대기, 실패·재시도, 조회 데이터 없음, 동기화 지연입니다. 출처 패널은 문서명·버전·관련 구절을 보여줍니다. 접수 후 중복 접수 버튼은 비활성화하고 기존 티켓으로 안내합니다.

첨부파일 기능은 이번 필수 범위가 아닙니다. 목업의 클립·더하기 아이콘은 시각적 예시이며 실제 구현에서는 제거합니다. 예상 응답 시간은 SLA 기준 확정 전 표시하지 않습니다.

배정은 유형별 팀 안에서 처리 가능한 사람 중 미완료 티켓이 가장 적은 사람을 고릅니다. 동률은 마지막 배정이 오래된 순, 다시 동률이면 고정 ID 순입니다. 전원 부재 시 팀 대기열에 남깁니다. 해결·종료 건은 업무량에서 제외합니다. 동시 배정 시 건수 갱신을 일관되게 처리합니다. 재배정은 사유를 기록합니다.

## 일정과 검증
첫 주: 역할·상태·API·화면 도구·지표를 고정하고 Jira 생성·조회·배정·상태 변경을 시험합니다.
둘째 주: 더미 데이터로 챗봇→티켓→대시보드를 연결합니다.
셋째 주: 실제 검색·분류·Jira를 연결해 10.23 대표 시나리오를 검증합니다.
넷째 주: 10.30 기능 범위를 고정하고 실패·중복·모바일·접근 제어를 검증합니다.
다섯째 주 이후: 기능 추가를 멈추고 평가·시연·발표와 복구 절차를 준비합니다.

평가 질문은 50개 제안이며 일반 20, 모호한 입력 10, 긴급 10, 근거 없음·범위 밖 10입니다. 검색 자료와 평가 자료의 복사·변형 중복을 제거합니다. 유형 정확도 85%, 우선순위 정확도 80%, Recall@3 85%, 긴급 평가 10건 누락 0건은 합의 전 목표입니다. 표본 수와 항목별 결과를 함께 보고하며 운영 성능을 보장하는 수치로 해석하지 않습니다.

AI 자체 해결률은 전체 유효 문의 중 사용자 해결 확인·티켓 미전환 비율입니다. 유효 문의는 테스트·빈 입력·명확한 중복을 제외한 실제 평가 문의로 정의하고, 범위 밖 문의의 포함 여부를 평가 시작 전에 고정합니다. 이탈·무응답은 해결로 집계하지 않습니다. 평균 배정 시간은 배정 완료 건을 대상으로 계산하고 미배정·실패 건수를 함께 표시합니다. 오배정률은 오배정 사유로 재배정된 고유 티켓 수/전체 티켓 수입니다.

필수 시연: 매뉴얼 해결, 유사 이력 후 티켓 전환, 추가 질문, 긴급 접수, 근거 없음, Jira 실패·중복 방지, 상태 동기화, 모의 모드, 모바일, 확인되지 않은 요약 방지, 본인 외 문의 접근 차단.

실제 과제 5번 원문·평가표는 제공되지 않았으므로 과제 필수 요건과의 대조는 별도로 필요합니다.
