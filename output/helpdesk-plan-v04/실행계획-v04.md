# IT 헬프데스크 AI 에이전트 실행계획 v0.4

상태: 팀 회의 검토안. 아래 사람별 배치는 확정된 역할이 아니라 실행 가능성을 검토하기 위한 제안이다. 역할 동의, 주당 투입 시간, 실제 기술 경험을 확인한 뒤 확정한다.

기간: 기존 계획의 10.01 시작~11.11 리허설을 유지한다. 현재 10.02 기준으로 남은 첫 주 작업을 계획한다. 휴일과 개인 일정은 가용시간 확인 후 반영하며 날짜 범위를 실제 작업일 수로 간주하지 않는다.

## 1. 이번 수정의 핵심

- 역할명만 배분하지 않고 매주 확인할 산출물과 인계 상대를 정한다.
- 첫 주에 기획·화면·API·데이터가 같은 문의 사례를 기준으로 병행 작업한다.
- 둘째 주 목표는 문의 하나를 입력해 티켓 목록에 한 줄 표시하는 최소 흐름이다. 완성형 대시보드나 AI 품질 개선을 포함하지 않는다.
- 모든 검토를 팀장에게 모으지 않는다. 기능별 협업자가 먼저 확인하고 구조 변경과 공통 장애만 기술 리드에게 올린다.
- 숙련 개발자가 핵심 경로를 책임지고, 초급 개발자는 더미 데이터로 독립 개발 가능한 화면부터 맡는다.
- 매주 최소 산출물을 우선 완료하고, 여유가 생기면 확장 작업을 가져온다. 팀원의 실제 업무량을 동일하다고 가정하지 않는다.

## 3. 범위

필수: 문의 입력, 필요한 추가 질문, 유형·우선순위 분류, 근거 있는 답변, 사용자 해결 확인, 미해결·긴급 접수, 한 가지 자동 배정, 직원의 본인 티켓 조회, 기본 집계, 명시적 모의 모드.

직원은 자체 화면, 담당자는 실제 Jira, 관리자는 자체 대시보드를 사용한다. 자체 Jira 복제 화면은 만들지 않는다. 모바일은 동일 화면의 반응형이다.

배정은 유형별 팀 → 처리 가능한 담당자 중 미완료 티켓 최소 순으로 한정한다. 동률·부재·기타 유형의 처리 규칙을 첫 주에 확정한다.

확장: 복수 배정 알고리즘, 별도 모바일 앱, 첨부파일, 문서 관리 UI, 복잡한 설정 화면, SLA 자동 관리, 고급 차트. 기본 배정 설정은 초기 설정 파일·데이터로도 가능하며 관리자 편집 UI는 여유가 있을 때 추가한다.

## 4. 첫 주 실행 순서: 완성본을 기다리지 않는다

### 10.02: 최소 기준 합의

- 전원: 역할 선호·가용시간 확인. 필수 범위와 추가 제외 항목 합의.
- 김현우: VPN 문의 대표 시나리오와 정상·미해결·긴급·정보 부족 분기를 1쪽으로 작성.
- 이민식·박민경: 공통 실행 방식, 데이터 저장 위치, API 경계 초안 합의.
- 고나영·김태연: 화면 흐름 스케치와 실행 환경 확인 시작.
- 김현나: 해당 문의의 매뉴얼·과거 해결 사례·평가 질문 초안 준비.

### 10.05~10.06: 최소 계약 공유

- 김현우·박민경: 상태, 우선순위, 배정·해결 기준 초안.
- 박민경: 메시지·티켓 생성·조회 응답 예시, 필수값·오류값·ID 관계 초안.
- 고나영: 챗봇·접수·조회 핵심 화면 초안. 김태연은 레이아웃과 더미 응답 구현 시작.
- 김현나: 소량의 검수 자료와 검색 반환 예시 제공. 전체 데이터 완성을 기다리지 않음.
- 이민식: 모두 실행할 수 있는 기본 구조 제공, 에이전트가 호출할 기능 경계 확정.

### 10.07~10.08: 연결 준비 완료

- API 예시 1세트, 핵심 화면 초안, 상태·지표 정의를 버전으로 고정.
- 박민경: Jira 생성·조회·배정·상태 변경 최소 시험. 이슈 필드·권한 문제를 이때 발견.
- 김태연: 더미 문의와 티켓 목록 표시. 고나영이 구현 차이 검수.
- 김현나: 소량 검색 시험과 독립 평가 질문 준비.
- 김현우: 모든 산출물이 같은 시나리오·용어를 쓰는지 인수 확인.

첫 주 공동 완료 기준: 문의 사례 1개 + 화면 초안 + API 응답 예시 + 검수 자료 + Jira 시험 결과 + 각자 로컬 실행 확인. 결정을 못 내린 항목에는 책임자·대안·기한을 기록한다.

### 주차별 공동 통과 기준

- 1주 말: 각 파트가 같은 시나리오·ID·상태·응답 예시를 사용하고 독립적으로 작업 가능.
- 2주 말: 문의 1건 → 고정 답변 → 접수 → 티켓 목록 한 줄. 실제 Jira 티켓 생성 확인. AI 답변은 더미여도 됨. 실패하면 성공처럼 표시하지 않음.
- 3주 말: 근거 기반 해결, 미해결 티켓 전환, 정보 부족 추가 질문, 긴급 접수, 근거 없음의 대표 흐름 실행. Jira 상태 변경이 자체 화면에 반영됨.
- 4주 말: 필수 기능 추가 종료. 중복·시간 초과·배정 실패·본인 외 조회·모바일·평가의 필수 수용 기준 검증.

Jira 접근 장애로 2주 목표를 못 맞추면 모의 흐름만 시연하고 Jira 연동은 미완료로 기록한다. 10.23까지 실제 연동을 해결하지 못하면 과제 요구사항을 확인해 범위·계획을 팀에서 재결정하며, 모의 모드로 완료 처리하지 않는다.

## 8. 팀장 병목 줄이기

- 화면 디자인·문구: 고나영↔김태연.
- 화면 API 연결: 김태연↔박민경. 박민경은 계약·오류 확인 위주로 지원하며 화면을 대신 전부 구현하지 않는다.
- 운영 정책 구현: 김현우↔박민경.
- 데이터 정답·평가 기준: 김현나↔김현우.
- 검색과 에이전트 연결: 김현나↔이민식.
- 공통 구조·여러 기능에 걸친 장애: 이민식↔박민경.

검토 요청은 작은 변경 단위로 하고, 고정된 짧은 지원 시간을 둔다. 화면 CSS·문구 변경까지 기술 리드 승인을 기다리지 않는다. 이민식은 공통 구조와 에이전트 핵심 경로를 우선한다.

## 9. 실제 업무량 조정 규칙

- 첫 회의에서 주당 가용시간을 적고, 본인이 작업 소요를 범위로 추정한다. 현재 표만으로 균등 배치라고 확정하지 않는다.
- 계획 작업은 가용시간의 약 70~80% 이내로 잡는 안을 검토하고 나머지는 리뷰·통합·예상 밖 오류에 남긴다.
- 각자 동시에 진행하는 주 작업은 1개, 지원 작업은 1개 이하를 기본으로 한다.
- 매일 공유: 완료 산출물, 다음 산출물, 막힌 이유, 누구의 무엇이 필요한지.
- 반나절 이상 막히면 같은 협업 상대와 공유한다. 해결이 오래 걸리면 더미·축소안으로 독립 작업을 진행한다.
- 매주 말 실제 완료·남은 작업·다음 주 가용시간으로 재배치한다. 여유가 있다고 무관한 핵심 개발을 맡기지 않는다.

### 과부하 발생 시 조정 순서

1. 추가 차트·관리자 설정 UI·장식·데이터 양 확대를 미룬다.
2. 김태연이 막히면 화면 수를 줄이고 공통 컴포넌트를 제공한다. 핵심 API 연결 한 경로부터 완성한다.
3. 김현나의 검색 구현 지원이 많이 필요하면 검증된 단일 검색 경로로 제한한다. 데이터 초안은 전원이 소량씩 분담하고 김현나가 검수한다.
4. 박민경이 밀리면 복잡한 설정·알림 확장을 제외하고 생성·조회·배정·동기화·중복 방지를 우선한다.
5. 이민식이 밀리면 지원 요청을 기능 협업자로 돌리고 에이전트 흐름을 단순하게 고정한다. 필요시 박민경에게 명확히 한정된 공통 기반 작업을 옮기되 양쪽 업무량을 재확인한다.

여유 작업: 고나영은 구현 검수·사용성 사례, 김현우는 인수 사례·운영 예외, 김현나는 오류 분석, 김태연은 화면 재현 확인. 핵심 일정에 영향 없는 추가 기능은 팀 승인 전 시작하지 않는다.

## 10. 평가·기능 완료 원칙

AI 자체 해결은 사용자 확인·티켓 미전환 건만 인정한다. 무응답·이탈은 미확인이다. 문의·티켓·연동 상태를 구분한다. 확인되지 않은 영향 인원·조치 결과를 AI 요약에 추가하지 않는다.

검색 자료와 평가 질문을 분리한다. 유형·우선순위 정확도, 긴급 누락, 정답 문서 검색, 접수·배정 성공 및 실패를 각각 확인한다. 수치 목표는 평가 세트와 팀 역량을 확인한 뒤 확정하고 실측 결과와 제안을 구분한다.

기능 완료는 화면 존재가 아니라 합의한 시나리오 실행·오류 표시·저장 결과·필요한 검토가 확인된 상태이다. 과제 원문·평가표가 제공되지 않았으므로 첫 주에 필수 요건과 대조해야 한다.

## 11. 첫 회의에서 확정할 사항

1. 잠정 역할에 대한 본인 동의와 주당 가용시간.
2. 필수 기능·확장 기능 및 과제 평가표 대조.
3. 첫 주 인계물의 작성자·기한·검토자.
4. 둘째 주 최소 시연 범위.
5. 이민식·박민경의 지원 가능 시간과 검토 분담.
6. 매주 범위·업무량을 재조정하는 시간.

회의 후 이 문서의 제안 상태를 항목별로 확정·수정·보류로 바꾸고 변경 사유를 기록한다.
